1. Introduction

This report describes the design and implementation of a complete interpreter for the RPAL (Right-reference Pedagogic Algorithmic Language) programming language. The project was implemented in C (C99 standard) and covers the full pipeline required:

  1. Lexical Analysis – tokenising the RPAL source text
  2. Parsing – constructing an Abstract Syntax Tree (AST) from the token stream according to the RPAL grammar
  3. Standardization – converting the AST into a Standardized Tree (ST)
  4. Evaluation – executing the ST on the CSE (Control-Stack-Environment) machine

No external tools such as lex, yacc, or any parser-generator were used. All components are implemented from scratch.

3.2 Lexical Analyzer (lexer.c / lexer.h)

The lexer implements the RPAL lexical specification (RPAL_Lex.pdf). It processes the source character-by-character and emits tokens one at a time on demand (lazy/pull model). It tracks line and column numbers for error reporting.

Key Data Types

typedef enum TokenType {
    TOKEN_IDENTIFIER,  /* letters, digits, underscore */
    TOKEN_INTEGER,     /* digit sequence               */
    TOKEN_OPERATOR,    /* symbol operators + word ops  */
    TOKEN_STRING,      /* single-quoted literal        */
    TOKEN_PUNCTUATION, /* ( ) ; ,                      */
    TOKEN_KEYWORD,     /* let in where fn within rec   */
                       /* true false nil dummy         */
    TOKEN_EOF,
    TOKEN_ERROR
} TokenType;

typedef struct Token {
    TokenType    type;
    char        *lexeme;   /* heap-allocated; free with token_destroy() */
    unsigned long line;
    unsigned long column;
} Token;

typedef struct Lexer {
    const char   *source;
    unsigned long position;
    unsigned long line;
    unsigned long column;
} Lexer;

Public Function Prototypes

/* Initialise the lexer with the source string (not copied). */

/* Return the next token from the stream; caller must call token_destroy(). */
Token       lexer_next_token(Lexer *lexer);

/* Free the heap-allocated lexeme inside a token. */
void        token_destroy(Token *token);

/* Return the printable name of a TokenType (e.g. "IDENTIFIER"). */
const char *token_type_name(TokenType type);

3.3 Abstract Syntax Tree (ast.c / ast.h)

The AST is represented as a first-child / next-sibling binary tree. Each node stores a heap-allocated label string. This layout naturally represents n-ary trees while using only two pointers per node.

Key Data Type

typedef struct ASTNode {
    char           *label;        /* node label (operator, keyword, or value) */
    struct ASTNode *first_child;  /* leftmost child                           */
    struct ASTNode *next_sibling; /* right sibling                            */
} ASTNode;

Public Function Prototypes

/* Allocate and initialise a new node with the given label. */
ASTNode *create_ast_node(const char *label);

/* Append child as the last child of parent. */
void     add_child(ASTNode *parent, ASTNode *child);

/* Append sibling after the last sibling of node. */
void     add_sibling(ASTNode *node, ASTNode *sibling);

/* Print the tree using dot-indentation (raw labels). */
void     print_ast(ASTNode *root, int depth);

/* Print the tree using typed leaf notation: <INT:n>, <STR:'s'>, <ID:x>. */
void     print_ast_pretty(ASTNode *root, int depth);

/* Recursively free an entire subtree. */
void     free_ast(ASTNode *root);

3.4 Parser (parser.c / parser.h)

The parser is a hand-written recursive-descent parser that directly implements the RPAL grammar (RPAL_Grammar.pdf). Each non-terminal in the grammar corresponds to one static parse_X function. The parser operates in a single left-to-right pass over the token stream, building the AST bottom-up.

Key Data Type

typedef struct Parser {
    Lexer *lexer;       /* token source                      */
    Token  current;     /* current look-ahead token          */
    int    has_current; /* whether current holds a valid tok */
    int    had_error;   /* set on first parse error          */
} Parser;

Public Function Prototypes

/* Bind the parser to a lexer; must be called before parser_parse(). */
void      parser_init(Parser *parser, Lexer *lexer);

/* Parse a complete RPAL program and return its AST root (or NULL on error). */
ASTNode  *parser_parse(Parser *parser);

3.5 Standardizer (standardizer.c / standardizer.h)

The standardizer transforms the parsed AST into a Standardized Tree (ST) by applying the RPAL standardization rules. It performs a recursive post-order traversal; nodes whose labels match a standardization rule are rewritten, while all other nodes are copied unchanged.

Public Function Prototype

   Returns a freshly allocated ST; caller must free_ast() the result. */
ASTNode *standardize_ast(ASTNode *root);

3.6 CSE Machine (cse.c / cse.h)

The CSE (Control-Stack-Environment) machine is the execution engine. It recursively evaluates a standardized tree using environments for name binding and applies lambda closures to arguments. Built-in RPAL functions are handled by a dedicated dispatch function.

Public Function Prototype

/* Evaluate the standardized tree rooted at root.
   Prints the result to stdout. Returns 0 on success, non-zero on error. */
int cse_evaluate(ASTNode *root);

Value Representation

typedef enum ValueType {

    VALUE_STRING,   /* string                           */

3.7 Main Module (rpal20.c)

The main module wires the pipeline together and handles CLI arguments. It supports four modes of operation:

  • ./rpal20 file – full execution (lex → parse → standardize → evaluate)
  • ./rpal20 -tokens file – print the token stream and exit
  • ./rpal20 -ast file – print the AST before standardization and exit
  • ./rpal20 -st file – print the standardized tree and exit

Static Functions

/* Run only the lexer and print all tokens. */

/* Run lexer + parser + standardizer and print the ST. */
static int print_standardized_tree_from_source(const char *source);
